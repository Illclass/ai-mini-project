# ChemBridge frontend

Vue 3 + Vite. 서진님 청록 테마를 적용하고 최신 지훈 브랜치의 Java 회원가입·로그인과 RAG 질문·답변 연결을 유지합니다. 검색 브랜치 병합 후 음성 입력·재생은 실제 STT/TTS API를 사용합니다(ko/zh/vi/en, km는 글 질문만).

## 실행

루트 README의 백엔드 설정을 먼저 준비합니다. 인증 서버에는 실제 `DB_PASSWORD`, `JWT_SECRET`이 필요하고 RAG에도 같은 `JWT_SECRET`을 전달해야 합니다. OpenAI 키는 RAG 서버에서만 사용합니다.

```sh
# 저장소 루트, 별도 터미널
./dev.sh --voice  # 실제 음성 기능까지 사용할 때
# frontend/
npm ci
npm run dev
```

http://localhost:5174 에서 회원가입 후 로그인합니다. 실제 계정 없이 로그인할 수 있는 디자인 모드는 제거했습니다. `dev.sh`는 프론트를 실행하지 않습니다.

## 연결

Vite가 동일 출처 요청을 아래 서버로 프록시합니다. 쿠키는 `credentials: include`로 전달하며 JWT는 프론트에서 읽거나 저장하지 않습니다.

| 경로 | 대상 | 처리 |
|---|---|---|
| `/api/signup` | Java :8080 | form 전송, 성공 리다이렉트 수신 후 로그인 폼 |
| `/api/login` | Java :8080 | form 전송, 성공 후 인증 쿠키 확인 |
| `/api/auth/check` | Java :8080 | 새로고침 시 로그인 상태 확인 |
| `/api/logout` | Java :8080 | 쿠키 삭제 후 인증 종료 확인 |
| `/rag-query` | FastAPI :8001 | 질문·영역·언어 전송, 실제 답변·출처 표시 |
| `/health` | FastAPI :8001 | 서버·인덱스 상태 |

배포 서버에서도 같은 경로로 reverse proxy를 구성해야 합니다. `npm run preview`는 정적 빌드 확인용으로 API 프록시를 제공하지 않습니다.

- 화학물질 안전·중대재해 법령 선택, ko/zh/vi/en/km 지원.
- 추천 질문에는 제품 번호 대신 장비명·약품명만 넣습니다. 장비별 작업 단계(공급라인·탱크·슬러리·배기 등)와 제품별 확인 사항(희석 발열·전용 응급 절차·용기 압력 등)을 별도 표에서 선택합니다. 6개 작업 상황별 2개씩 구분하고 선택한 장비·제품에 맞춰 즉시 갱신합니다. 제품별 질문 주제를 사용하며, 보관 질문을 다른 모든 카드에 반복하지 않습니다. 대화가 시작된 뒤에도 현재 선택에 맞는 질문 버튼을 제공합니다.
- 장비만 선택하고 제품을 고르지 않은 화학 질문은 입력을 유지한 채 “어떤 약품인지 선택해 주세요”를 표시합니다. 안내 버튼으로 해당 장비의 제품 선택창을 열며, 선택 후 직접 전송합니다. 자동 전송하거나 약품을 추정하지 않습니다.
- 로딩: 실제 요청이 끝날 때까지 대기 표시, 12초 후 지연 안내, 수동 취소 지원. 임의 진행률이나 성공 답변은 만들지 않습니다.
- 질문 실패·취소: 질문과 원래 선택값을 대화에 유지합니다. 재시도는 같은 요청을 보내며, 질문 수정은 원래 장비·제품과 입력을 복원합니다. 화면 이동 시 요청 취소.
- 담당자 확인: 밝은 노란 배경과 어두운 글씨로 가독성을 높였습니다. 검토·handoff는 실제 비상 상황 판정과 구분 없이 붉게 표시하지 않습니다.
- RAG 401: 로그인 화면으로 이동하고 작성 질문을 메모리에 보관, 재로그인 후 복원. 자동 재전송하지 않음.
- 422·503·연결 실패·시간 초과: 해당 언어로 오류 표시.
- `handoff`는 담당자 확인 경고, `needs_review`는 추가 확인 안내.
- 출처 제목·조항과 실제 http(s) 원문 링크 표시. 원문 링크가 없으면 문서 정보만 표시.
- 회원가입: 비밀번호 확인·중복 아이디 안내. 서버의 trim/BCrypt 특성 때문에 앞뒤 공백과 72바이트 초과 비밀번호는 가입 전 차단.
- 계정·비밀번호·토큰·대화는 브라우저 저장소에 보관하지 않음. 선택 언어만 저장. 새로고침하면 대화는 초기화.
- 화학 질문의 장비·제품 선택을 지원합니다. 장비 변경 시 연결되지 않은 제품을 해제하며, 법령 질문에는 두 ID를 보내지 않습니다(각 `null`). 재시도는 최초 질문의 선택값을 유지하고, 401 후 재로그인 시 작성 질문과 선택값을 복원합니다.
- 장비는 공통 `rag-service/data/equipment_map.json`의 시연용 가상 장비입니다. 제품은 `ingest_all.sh`의 MSDS 목록에서 가져옵니다. 자료가 전혀 없는 장비는 선택 목록에서 제외합니다. 일부 자료만 있는 장비는 등록된 제품만 선택할 수 있고 확인 안내를 표시합니다. 문서 ID·제목이 없는 제품도 제외합니다. 장비 목록 API는 사용하지 않습니다.
- 생성과 근거 검증에 각각 시간이 걸리므로 질문 요청 제한 시간은 90초입니다. 백엔드가 제품 식별·농도·개정일을 확인하지 못하면 정상 답변 대신 `handoff`가 나올 수 있습니다.
- 현재 질문은 각각 독립 요청. 대화 이력을 백엔드에 보내는 계약은 없음.
- 음성 입력·듣기·음성 대화는 실제 녹음/STT/TTS 기능입니다. `./dev.sh --voice`로 :8008을 함께 실행해야 합니다. 마이크 권한은 사용자가 음성 기능을 켤 때 요청하며, km는 음성 기능을 제공하지 않습니다.
- 로컬 인덱스가 없으면 답변·출처 생성 검증이 제한되며, 백엔드의 근거 없음/handoff 응답을 그대로 표시.

## 공통 계약과 검증

프론트에서 Python 모듈을 직접 import할 수 없어 `rag/schema.py`를 읽는 생성기로 공개 계약 JSON을 만듭니다. 백엔드 계약 변경 시 재생성하고 diff를 확인합니다.

```sh
# 저장소 루트
.venv/bin/python frontend/scripts/generate-contract.py
.venv/bin/python frontend/scripts/generate-contract.py --check
.venv/bin/python frontend/scripts/generate-catalog.py
.venv/bin/python frontend/scripts/generate-catalog.py --check
cd frontend
npm test
npm run build
# 저장소 루트/rag-service
../.venv/bin/python -m pytest -q tests
```

`src/api/client.js`는 요청·응답 검증, `src/api/contract.json`은 공유 계약, `src/locales/api.js`는 API 상태 문구, `src/App.vue`는 인증·질문 상태를 담당합니다. 기존 CSS 위에 `src/clean-theme.css`를 적용합니다. PDF 렌더링·책 넘김에 서진 브랜치의 `pdfjs-dist`와 `page-flip`을 추가했으며 package.json/lock에 기록합니다. PDF 뷰어는 필요할 때 별도 청크로 불러옵니다.

## bge-m3 인덱스 적용

retriever 브랜치의 기본 임베딩은 `bge-m3`입니다. `sentence-transformers`는 이미 서버 requirements에 포함돼 있으며 첫 실행에 모델 다운로드가 필요합니다. PDF 추출에는 `pdftotext`(macOS: `brew install poppler`)를 사용합니다. 적재와 서버 검색은 반드시 같은 임베딩 모델로 실행해야 합니다.

기존 OpenAI 인덱스는 먼저 별도 경로에 백업합니다. `rag-service/ingest_all.sh`의 27개 문서를 처리한 뒤 법령·MSDS 인덱스의 문서 수, 벡터 차원, 출처를 확인하고 RAG를 재시작합니다. 이 스크립트는 기존 인덱스를 삭제하므로 실행 전 백업이 필요합니다. 로컬 검증에서는 `.venv/index-backups/`에 백업하고 `.venv/index-staging/`에서 새 인덱스를 완성한 뒤 교체합니다. 모델·인덱스·백업은 Git에 올리지 않습니다.

영어·크메르어는 로그인·회원가입·메인·질문·API 오류 문구를 모두 지원합니다. 크메르어는 전용 글꼴/줄 간격을 사용합니다. 메인 제목과 카드 설명은 서진님 레이아웃을 따릅니다. 번역 문구는 현장 배포 전 원어민 검토가 필요합니다.

## 로컬 화면 검증 (2026-10-23)

자료 없는 장비 제외, 카드·장비·제품별 추천 질문 갱신, 실제 질문 요청을 확인했습니다. 응답 지연·취소·503·재시도·질문 수정은 별도 임시 로컬 테스트 서버로 검증한 뒤 종료했습니다. 기본 개발 서버는 계속 5174이며 배포 코드에 테스트 응답이나 별도 서버 주소를 넣지 않습니다. 검색·생성 보류 원인 수정은 백엔드 담당 범위입니다.

추천 질문 문장 회귀 검사는 미선택·장비만·제품만·장비+제품의 37개 선택 조합 × 7개 상황(자유 질문 포함) × 5개 언어 × 2개 질문, 총 2,590개 문장을 검사합니다. 약품명 중복, 사고/접촉 시 표현 중첩, 절차 반복, 빈 값·템플릿 잔여·제품 ID 노출을 확인합니다. 추천 질문은 `api/recommendations.js`의 등록 문서·항목과 `locales/recommendations.js`의 다국어 문장으로 생성합니다. 중복 조합되던 기존 `questions.js`·`question-checks.js`는 제거했습니다.


## 서진 디자인·PDF·보고서 통합 (2026-10-23)

- 기준: 지훈 브랜치 `ccf7c9a` 위에 서진 브랜치 `cfe66e5`의 화면·청록 테마·로고와 PDF/보고서/연락망을 이식합니다. API client·공통 계약·장비/제품 목록·추천 질문 중복 수정은 기존 최신 코드를 유지합니다.
- Enter로 질문을 보내고 Shift+Enter로 줄바꿈합니다. IME 조합 중 Enter는 전송하지 않습니다. 영역 탭을 옮겨도 작업 상황은 유지하고 대화와 선택값은 초기화합니다.
- 자유 질문 FAQ는 장비·제품 미선택 상태에서 표시합니다. 선택값이 있으면 최신 장비·제품별 추천 질문을 사용합니다.
- 대표 지침서 7개는 저장소의 원본 PDF를 제공합니다. 작업 후 지침 `public/guides/after.pdf`는 최신 S1 원본과 동기화하며 바이트 일치 회귀 검사로 확인합니다. `api/guides.js`에서 실제 문서명·출처를 관리합니다. 작업 후 지침은 가상 현장 DEMO, 사고 지침은 불산 전용입니다. 불산 외 제품을 선택한 사고 화면에는 불산 PDF를 제시하지 않습니다. PDF는 한국어 원문이며 화면 언어에 따라 번역되지 않습니다. 대표 지침서와 답변의 실제 RAG 출처를 구분합니다.
- PDF는 책 넘김·원문 열람·다운로드, 로딩 실패 시 재시도를 지원합니다. 이동/교체 시 렌더링과 로딩을 취소하고 PDF 자원을 해제합니다. 작은 화면에서도 원문 링크와 뷰어를 제공합니다.
- 보고서는 최초 질문·영역·장비·제품·언어·응답을 복사해 사용합니다. 언어 변경은 동일 선택값으로 새 답변을 요청합니다(단순 번역 아님). 원문 질문은 유지하고, 언어별 결과를 캐시하며 새 언어 선택·닫기 시 진행 중 요청을 취소합니다.
- 보고서에도 handoff/needs_review 경고와 실제 출처 전체를 `[1]`, `[2]` 순서로 표시합니다. 공유 텍스트에도 선택 범위·출처 URL·경고를 포함합니다. 정적 인접 조항을 새 답변 근거로 추가하지 않습니다.
- 보고서 PDF 버튼은 시스템 인쇄 창의 **PDF로 저장** 기능입니다. 긴 답변은 여러 페이지로 출력될 수 있습니다. 실제 PDF 저장·프린터 선택과 외부 공유 대상 선택은 사용자가 진행합니다.
- 보고서 요청의 401도 기존 로그인 복구 흐름을 사용합니다. 재로그인 후 원래 질문·장비·제품·작업 상황을 복원하며 자동 재전송하지 않습니다.
- 비상 연락망은 공개 번호와 회사 연락처 미등록 표시만 제공합니다. 회사 연락처 저장 API는 없으며 등록된 것처럼 표시하지 않습니다. 모달은 Escape·Tab 포커스 순환·닫은 뒤 포커스 복귀를 지원합니다.

검증: 프론트 테스트 31개, 빌드, 계약/카탈로그 동기화, RAG 541개 통과(12개 제외). 실제 로그인·황산 질문(출처 7개)·한국어/영어 보고서, PDF 페이지 넘김을 확인했습니다. 영어 답변은 서버가 번역 검증 실패 시 handoff를 반환하며 그대로 표시합니다. 분리된 임시 응답으로 보고서 원래 ID 전송·401 복구·503 재시도·수정·요청 취소·모달 키보드 이동을 검증했고 테스트 서버는 종료했습니다. 시스템 인쇄 창 호출까지 확인했으며 최종 PDF 파일 저장은 브라우저 UI에서 사용자 확인이 필요합니다.

## 최신 검색 브랜치 통합 (2026-10-25)

실제 음성 API, 장비별 S1 검색, 실패 진단 표시, 출처 문서별 묶기까지 반영했습니다. 최신 S1 PDF 동기화·인덱스 재생성 및 통합 테스트 결과와 남은 WAV 업로드 문제는 [검증 기록](docs/retriever-integration-20261025.md)을 참고하세요. WAV 문제는 사용자 요청으로 기록만 남기고 수정하지 않았습니다.

## 모든 출처의 원문 바로 보기

MSDS 13종, KOSHA 지침 8종, 법령 5종, S1 현장지침 등 등록 문서 27개의 원본 PDF를 연결합니다. 질문 화면의 출처 카드에서 항목을 누르면 해당 물리 페이지로 이동하고, PDF 텍스트에서 제목을 찾으면 그 위치까지 스크롤합니다. 법령은 조·항·호를 구분하고 지침은 4.1 같은 소절 번호를 유지합니다. 출처 인용 번호는 그대로 유지하며 기관 홈페이지 링크는 별도로 제공합니다. 보고서에도 해당 페이지를 여는 원본 PDF 링크가 있습니다.

- 페이지 정보: `src/api/source-pages.json`. 알려지지 않은 문서·주소에는 페이지를 추정하지 않고 기존 링크를 유지합니다.
- `rag-service/data/` 원본을 Vite가 개발 서버에서 제공하고 `dist/assets/`에 포함합니다. PDF를 따로 복사해 커밋하지 않습니다.
- 등록된 한국어 시행·개정본이며 실시간 최신 문서라는 뜻은 아닙니다. 시행·개정일과 적용 범위를 확인해야 합니다. S1은 가상 현장 시연용입니다.
- 원문 변경 시 루트에서 `.venv/bin/python frontend/scripts/generate-source-pages.py`를 실행합니다. `--check`로 갱신 여부를 검사하며 프론트 테스트도 해시와 페이지 범위를 확인합니다. LLM·임베딩을 호출하지 않습니다.
- 원문 창은 이전·다음 페이지, 인용 항목 이동, PDF 새 탭 열기, Escape 닫기·포커스 복귀, 오류·재시도를 지원합니다.

## 근거가 있는 추천 질문 (2026-10-26)

카드·장비·제품별 추천과 자유 질문 FAQ를 같은 문서 항목 목록으로 생성합니다. 추천 문장은 보호구·취급·보관·폐기·화재 대비와 실제 작업 전후의 확인 사항을 자연어로 묻습니다. 문서명·항·절 번호는 질문에 표시하거나 덧붙여 전송하지 않으며, 근거 주소는 내부 검증용 `targets`로만 유지합니다. 실제 사고를 신고하는 예문과 미등록 물질·구체적인 장비 조작·혼합 비율을 묻는 추천은 제외합니다. 실제 사고를 직접 입력할 때의 긴급 안내와 서버 검증은 유지합니다.

FAQ 약품 질문을 누르면 해당 `product_id`를 선택하고 질문을 입력합니다. 자동 전송하지 않으며, 일반 질문을 쓸 때 제품 선택은 사용자가 해제할 수 있습니다. 추천 문구에 제품 번호를 노출하지 않습니다. 등록된 원문에서 확인되지 않는 제품별 차이를 만들어내지 않습니다.

FAQ 변경 후 `node frontend/scripts/generate-recommendations.mjs`로 `candidates.json`을 갱신합니다. `--check`는 일치 여부만 검사합니다. 5개 언어의 카드·선택 조합 2,590문장과 FAQ·법령 145문장, 총 2,735개에 대해 원문 항목 주소·중복·길이·제품명 및 제품 ID 연결을 검사합니다. 자료가 있다는 사실이 생성·번역 검증 성공을 보장하지는 않으며, 서버의 보류·오류는 그대로 표시합니다.

로컬 인덱스가 있으면 `.venv/bin/python frontend/scripts/check-recommendation-sources.py`로 추천의 모든 근거 주소가 적재돼 있고 현재 검색기의 제외 대상이 아닌지 확인할 수 있습니다. 사전 보류 규칙도 5개 언어 전체에 적용하며 LLM은 호출하지 않습니다.

추천 문장을 바꾸면 실제 RAG 요청의 `question`도 같은 문장으로 바뀝니다. 화면용 문장과 검색용 문장을 따로 두지 않습니다. `api/recommendations.js`는 문서·범위를, `locales/recommendations.js`는 작업자가 말하는 질문 문장과 장비별 작업 맥락을 관리합니다. 문서·항·절을 추천 문장에 넣지 않는 회귀 검사를 포함합니다.


## dev 병합 및 대화 레이아웃 유지 (2026-10-26)

`dev`의 `0ec8aca`를 병합했습니다. PDF는 기본 접힘이며 왼쪽 화살표 하나로 펼치고 접습니다. 25% 단위 100~300% 확대·축소와 페이지 전체 보기, 확대 중 페이지 이동을 유지합니다. 장비·제품 고정 선택, 대화만 스크롤, 접을 수 있는 추천 질문, 자동 확장 한 줄 입력창과 음성 아이콘도 유지합니다.

중복되던 dev의 지침서 버튼·자동 접기·선택창/입력창 크기·페이지 전체 스크롤 처리는 현재 레이아웃으로 통일했습니다. 긴 정보 목록의 앞 3개 표시 및 더 보기/접기는 반영하며, 주의사항은 접지 않습니다. 보고서·음성은 원래 전체 응답을 사용합니다.

검증: 프론트 72개, RAG 876개 통과(12개 제외), 프론트 빌드, 계약·카탈로그·원문 페이지·추천 질문 동기화 검사 통과. 별도 임시 응답 환경에서 목록 접기/펼치기·주의사항 유지·고정 레이아웃·추천 질문 접기와 PDF 200% 확대/페이지 이동을 확인했습니다. 실제 LLM 요청·음성 서버 재검증은 이번 병합 검사에 포함하지 않았습니다.

## 브라우저 화면 이동과 Docker PDF 수정 (2026-10-26)

Vue Router 4를 추가했습니다(`package.json`·잠금 파일에 기록). `/login`, `/home`, `/chat/:situation` 경로를 사용하고 법령 영역은 `?topic=serious_accident_law`로 구분합니다. 브라우저 뒤로가기·앞으로가기와 직접 주소/새로고침을 지원하며, 각 이동에서 실제 세션을 확인합니다. 미인증이면 로그인으로 이동하고 로그인 후 원래의 내부 화면으로 복귀합니다. 외부 URL을 로그인 복귀 주소로 사용하지 않습니다.

401 재로그인의 작성 질문·선택값 복구를 유지합니다. 대화는 서버나 브라우저 저장소에 추가 저장하지 않으므로 새로고침 시 답변은 초기화됩니다. 앱 진입 이전 사이트로 돌아가는 브라우저 동작 자체를 막지는 않습니다.

Docker Nginx가 PDF.js의 `.mjs` 워커를 `application/octet-stream`으로 보내던 문제를 수정했습니다. `application/javascript`로 제공해 책자와 출처 조항 원문 뷰어가 로딩되도록 했습니다. 배포 smoke 검사도 실제 빌드 청크를 따라가 워커 MIME과 등록 원문 PDF 27개를 확인합니다.
